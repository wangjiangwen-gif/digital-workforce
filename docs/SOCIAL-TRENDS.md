# 社媒热点分析员工

本场景提供可初始化的数字员工配置、三个 MA Skill，以及一套可调整的依赖契约。四维洞察、样本阈值、发布时间均为平台初版设计，尚未经过具体业务验收。

## 初始化

数字员工列表 →「初始化数字员工」→ 选择「社媒热点分析员工」或「ADA」。

- 未配置方舟 Key：仅保存员工配置、知识、规则和记忆模板，不伪造技能。
- 已配置 Key：核验或上传该场景的三个 Skill，从 MA 回读真实 ID 和版本后绑定员工。不会从 MA 拉取账户全部技能。
- 再次初始化复用员工，保留用户修改的身份、知识、记忆和技能启停状态，补齐场景配套技能。
- 模板初始化不创建飞书应用、不启动渠道；接入飞书时沿用现有 MA Agent / 环境 / Vault 创建流程。
- 方舟配置里的「一键初始化 MA 资源」支持已有 ADA 和社媒员工的资源恢复；先 Skill 后 Agent。此完整资源流程会暂停 Channel，仍需重启服务。
- 创建结果未知时保留 pending，避免重复上传；明确失败和缺失按原资源恢复规则处理。

## 三个 Skill

| Skill | 输入 | 输出 |
| --- | --- | --- |
| social-trend-data | 上传的 CSV/JSON 或已配置 MCP 的真实返回 | 规范记录、分层样本、质量报告、输入 SHA256 |
| social-trend-insights | 样本验收记录、规范数据、项目背景 | 事件宽表、记录与事件映射、四维洞察、待核验项 |
| social-trend-report | 事件与洞察、质量报告、交付模板 | Markdown / HTML 草稿；具备工具和授权后飞书文档及发布回执 |

数据准备 Skill 自带 Python 标准库脚本，不依赖 pandas。要求运行环境有 Python 3.9 或以上；系统 `zip` 用于服务端上传 Skill。脚本按平台和日期分层稳定抽样，默认最多 500 条，不自动批准样本，不估算未经测量的标注准确率。

## 依赖契约

| 依赖 | 默认方案 | 实际接入要求 |
| --- | --- | --- |
| 数据源 | 上传 CSV/JSON，未提供数据时请求文件 | 内部 MCP 工具名、参数 schema、分页、周期、限额、网络与凭证需真实验证 |
| 项目范围 | 人工指定项目与时间窗 | 群聊沿用已有群 → 项目映射；未来定时任务必须显式保存 project_id |
| 规则 | 配套 Knowledge、Skill 和方法记忆 | 业务验收分类、合并、筛选与评分口径；不得冒充已确认规则 |
| 飞书留档 | 本地 Markdown 草稿 | 真实飞书工具、目录位置、身份和写权限 |
| 网页交付 | 本地 HTML 草稿 | 托管目标、发布工具、凭证与授权；返回可核验 URL 才算上线 |
| 调度 | 人工启动 | 建议每周一 09:00，Asia/Shanghai，统计上一自然周；业务调度尚未实现，不同于现有零点记忆整理 |
| 阶段恢复 | 文件记录本轮状态，人工核对后继续 | 当前没有业务级持久化 checkpoint 引擎，不保证服务重启后自动继续 |

记忆中的 `config/dependencies.md` 是业务契约，不是平台自动执行的连接器或调度配置。修改它不会自动安装 MCP、挂载凭证、授权发布或开启定时任务。

## 输入与产物

记录必填：record_id、platform、title、source_url、published_at（含时区）。可选数值指标：views、likes、comments、shares、favorites、heat_value；缺失保留 null，真实 0 不丢失。

每轮采用独立 `run_id`；建议用项目、周期、数据 SHA256、规则与技能版本识别同一次逻辑任务。`runs/<run_id>` 存放原始数据、加工宽表、图表及报告。长期 Memory 仅保存已确认的方法、跨期事件判断、反馈和产物链接。文件中的运行清单不是平台调度数据库。

建议人工验收流程：准备 → 样本处理 → 样本验收 → 全量处理 → 报告草稿 → 确认 → 发布 → 完成。全量前必须确认当前数据和规则对应的样本。数据、规则或版本变化后重新验收。

四维洞察：热点格局、传播变化、内容机会、风险与行动。跨平台原始热度不直接相加；没有基期不计算增长；没有来源不产出事实结论。

## 验证方式

1. 初始化员工，确认三个技能均显示真实 MA ID 和版本。
2. 上传一个具有来源与周期信息的样本文件，请员工先输出质量报告和抽样结果。
3. 确认样本标注和事件合并后继续全量分析。
4. 获取含来源的 Markdown 与 HTML 草稿。
5. 配齐目标位置和权限后单独验证外部留档与发布。

模板及真实 Skill 上传通过不等于内部 MCP、飞书写入、网页发布或定时生产已联调通过。

## 最终产物验证

报告技能内置 `scripts/validate.py --run-dir <本轮目录>`，按 `references/validation-contract.md` 检查批次/周期/输入哈希、五类必需产物、事件来源引用、报告章节、未处理复核项及静态 HTML。失败返回非零并生成带错误码和文件位置的 `validation.json`；修正后重算文件清单再验证，最多两轮，仍失败则反馈阻塞原因。

通过仅表示 `draft_validated`。结论与原始证据、数值计算的语义一致性另由员工核对并输出 `semantic-review.md`；最终飞书/网页状态必须用实际服务回读，不能凭本地 URL 或自报状态宣称发布成功。当前是 Skill 内的交付验证流程，不是工作台对所有消息的服务端强制拦截器。

报告包修订为 `validator-v1`，初始化用独立 MA 资源回执升级引用，保留旧资源；重复初始化复用修订后的资源。已接入 MA Agent 的员工仍需按现有 MA 配置同步流程更新远端 Agent。
